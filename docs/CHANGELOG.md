# SND 逐版修訂紀錄（發現的問題 → 修正／更換的方法）

編號與時期依 `VERSIONING.md`。本檔取代「公開 AI 對話紀錄」：不公開對話原文，只記錄每一版**發現了什麼錯誤或矛盾、怎麼修正、更換了哪些驗證方式**。
類型標籤：【數學】公式或推導錯誤；【邏輯】敘述互相矛盾；【方法】驗證方式不足或更換；【數字】數值錯誤；【程式】腳本錯誤。

## 思路主線（一句話版）
「能不能抓到未來影響過去的痕跡？」→「哪些物理框架能導出可測的指紋？」→「放棄爭論機制，只問資料裡有沒有統計相依」→「用複雜機制保證覆蓋率與錯誤率」→「逐份審閱，發現保證多半證明不了」→「改成可證明的隨機化設計＋一個振幅上界，再逐版驗證」。每一步都是因為上一步被指出**無法檢驗或無法證明**而轉向。

### V2.0.12（公式排版修正）
來源：V2.0.11 的公式在 GitHub 上已能顯示，但作者指出「公式還是看起來不太對」「某些地方符號會異常高起」。作者用 GitHub 的 issue 預覽（不送出）貼上測試片段並附截圖，經數輪對照確認：100% 縮放下相同；用規範逐字的公式行貼進預覽也重現，所以不是縮放或規範頁面特有的問題。處置：
- 【原因】(1) `\bar f`：MathJax 的 `\bar` 是一小段短橫線，飄在字母的左上方，看起來像飄走的小點；`\overline{f}` 則畫出完整橫線。(2) 帶重音符號的量加平方，例如 `\widetilde f_{b,i}^{\,2}`：MathJax 把平方的 2 疊到波浪符號之上，使 2 被頂高；寫成 `(\widetilde f_{b,i})^{2}` 就回到正常高度。(3) 帽子（`\widehat`、`\hat`）蓋在高字母 f 上，本來就會落在 f 的頂端之上，屬正常排版；預覽中 `\widehat f`、`\hat f`、`\hat{f}` 三者畫出來相同，所以這一項**不改**。
- 【改動】只改兩類寫法，數學意義不變：`\bar X` → `\overline{X}`（含 `\bar{\widetilde f}_b`）；「帶重音符號的量＋指數」→ 括號包住該量再加指數（下標留在括號內；`^{\,2}` 的細空白因括號已分隔而省略）。工具 `code/scripts/render_fix.py`（含 `selftest`）；`check_math.py` 新增規則，之後這兩種寫法會被報為問題。
